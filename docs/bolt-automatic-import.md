# Automatic Bolt trip refresh

The server job refreshes the previous seven days three times daily. The prepared cron expression is `0 2,10,18 * * *` in UTC (Europe/Lisbon has the same clock in winter and is one hour ahead in summer). It uses the existing key kept in Vault; no key is sent to the browser, returned by the API or written to logs. Existing Cartrack/turn-review schedules remain separate.

The Edge Function authenticates either the scoped server key using the existing verification RPC, or the current administrator's JWT plus active profile and existing administrator email restriction. Invalid job keys fail closed even if another header is present. The scheduled path always uses seven days and the fixed company 9360, ignoring client range/company overrides. Gateway verify_jwt=false is required for the server-key path; the handler performs both authentication paths itself. Manual requests still verify their JWT with Supabase Auth and check the active administrator profile before reading input/OAuth/writes.

Apply `preserve-bolt-trip-history.sql` first. Missing incoming fields preserve existing trip fields. Conflicting driver/vehicle identifiers or plates reject the entire transaction; the conditional UPSERT also checks identities after locking a conflicting row, and a mismatched affected-row count raises an error to roll back the call. No driver lifecycle or vehicle assignment is changed. Function ownership and execute privileges are preserved. The rollback definition is saved separately; deactivate the job before restoring any older handler/SQL.

Deploy the reviewed handler with server-key authentication, validate rejection of unauthorized requests, then make one authenticated real import through the authorized connector. Compare existing row IDs, known-field presence and normalized identities before/after. This import must contain only actual Bolt data, never synthetic shifts/trips. Install `bolt-activity-scheduler.sql` only after the import and preservation checks pass. Do not activate a duplicate job.

Keep coverage_verified=false and snapshot_consistency_unverified=true in traces. Three automatic refreshes, a stable API count and complete pagination do not alone prove 28 days of absence on both platforms; the driver-inactivity safeguards and permanent Rúben exemption are unchanged. Failures remain failures and do not assert zero trips. Mileage for shift analysis remains exclusively Cartrack.

Validation includes the existing 37 Node tests, isolated native/lifecycle database tests and `tests/bolt-trip-history-db.mjs` for preservation, atomic conflict rejection, the conditional UPSERT guard exercised independently of the early precheck, unchanged privileges and inactive-driver preservation. These tests do not write production records.
